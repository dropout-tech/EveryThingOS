# 收年費與客戶健康度

這份寫的是 DropOut 向每家客戶公司收年費的流程（不是客戶自己的官網收款），以及營運後台的「健康度」怎麼算。程式在 `glue/src/billing.ts`、`glue/src/health.ts`，資料表在 `glue/migrations/0004_billing.sql`。

## 價錢

不用 AI 的公司不開帳單。AI 版（`plan` 為 `ai`）一年含稅 **NT$69,000**。帳單上的未稅與稅額用檔案裡既有的 5% 從這個含稅總額拆出來，加總仍是 69,000。價錢在 `glue/src/billing.ts` 的 `ANNUAL_TAX_INCLUDED_TWD`；官網在 `web/lib/commercial.ts`，兩邊要一起改。現在 AI 用量不限。以後會限量，上限和開始日要先寫在價格頁，並在到期前通知，這一期不會靜默改成限量。

付款頁、綠界、電子發票用的金額都從帳單那一筆讀，不看瀏覽器送來的任何數字。

## 流程

```
到期前 60 天（每天 02:00 排程）
  └ 開一張帳單：公司名稱、統編、發票地址、聯絡人 Email 從公司資料抄過來
      └ 續約提醒信附上付款連結；老闆在殼的提醒條和設定頁看到「線上付款」
          └ 點連結 → 膠水產生綠界付款頁（刷卡或 ATM）
              └ 綠界通知膠水 → 驗簽、對金額與交易編號
                  └ 帳單標已付 → 續約一年 → 推狀態給 ERPNext → 開電子發票
```

- **一期只開一張**：同一家公司、同一個到期日只會有一張未付或已付的帳單（資料庫唯一索引）。排程每天跑也不會重複開。
- **作廢**：營運作廢後排程不會自己再開；要重開請在營運後台按「開這期帳單」。已付款的不能作廢，要退款請到綠界後台，發票在加值中心作廢。
- **續約怎麼算**：從「目前到期日」和「今天（台灣時間）」取比較晚的那天加一年。準時付就接著原本的到期日；過期才付就從付款那天起算。跟營運後台的「續約一年」、導入工具的 `fleet renew` 是同一段程式，公司歷史會記一筆「續約」，做的人是 `payment`，後面附帳單編號和綠界交易編號。
- **線下付款**（匯款、支票）：營運後台填匯款末五碼或收款單號，按「標記已付款」，一樣會續約一年、開發票，歷史記下是誰按的。
- **重寄連結**：營運後台「寄付款連結」寄到公司聯絡人；沒設寄信就複製連結自己貼給客戶。
- **試用中的公司**沒有到期日，排程不會開帳單；簽約時由營運按「開這期帳單」，付款後從付款日起算一年。

### 失敗的時候

| 狀況 | 會怎樣 |
| --- | --- |
| 簽章不對、MerchantID 不對、交易編號不是我們產生的 | 回 400，什麼都不改 |
| 金額跟帳單不同 | 不續約，公司歷史記「付款金額不符」，請人工確認 |
| 綠界重送同一筆通知 | 回 `1\|OK`，不會再續約一次 |
| 已付過又收到另一筆付款 | 不再續約，歷史記「重複付款」，請到綠界退款 |
| 作廢的帳單收到付款 | 不續約，歷史記下來，請人工處理 |
| 綠界後台按「模擬付款」 | 只記一筆，不續約（測試要用測試卡真的走一次） |
| 綠界掛了、付款頁打不開 | 帳單還是未付，客戶可以晚點再點同一個連結；每次點都會產生新的交易編號 |
| 膠水沒設綠界 | 付款連結顯示「線上付款還沒開，請回信索取匯款資料」 |
| 電子發票開失敗（加值中心沒回應、缺地址…） | **續約照樣生效**。帳單上記錯誤原因，營運後台清單顯示「發票沒開成」；每天 02:00 自動重試，也可以按「重開發票」 |
| 續約寫入失敗 | 回 500 讓綠界重送，帳單已付但會在下一次通知補續約 |

電子發票的關聯編號用帳單編號。萬一加值中心其實開好了、只是回應沒送到，重試會被拒絕（編號重複），這時請到加值中心查，把發票號碼記下來。

## 要設定的東西

膠水（`wrangler secret put` 或 vars）：

| 變數 | 說明 |
| --- | --- |
| `BILLING_ECPAY_MERCHANT_ID` | DropOut 的綠界特店編號 |
| `BILLING_ECPAY_HASH_KEY`、`BILLING_ECPAY_HASH_IV` | 綠界後台「系統開發管理 → 系統介接設定」 |
| `BILLING_ECPAY_ENV` | 寫 `production` 才用正式付款頁 `payment.ecpay.com.tw`；沒寫或其他值都是測試環境 `payment-stage.ecpay.com.tw` |
| `BILLING_EINVOICE_MERCHANT_ID`、`BILLING_EINVOICE_HASH_KEY`、`BILLING_EINVOICE_HASH_IV` | 選用。綠界電子發票的帳號（跟金流是不同組金鑰）；沒設就不開，營運後台顯示「請在加值中心手動開」 |
| `BILLING_EINVOICE_ENV` | 寫 `production` 才用正式 `einvoice.ecpay.com.tw`，否則 `einvoice-stage.ecpay.com.tw` |
| `GLUE_PUBLIC_URL` | 膠水對外網址，例：`https://glue.dropout.tw`。續約提醒信裡的付款連結要用；沒設信裡就不附連結 |
| `RESEND_API_KEY`、`PLATFORM_MAIL_FROM`、`PLATFORM_NOTIFY` | 已經有的寄信設定，提醒信與「寄付款連結」共用 |

付款連結的簽名用 `TENANT_KEY` 算，不用另外設。資料表要先跑 `npm run db:migrate`（會套用 `0004_billing.sql`）。

殼和營運後台不用加新的變數：殼用原本的 `SHELL_TOKEN` 只讀得到自己那家未付的帳單，營運後台用原本的 `GLUE_ADMIN_TOKEN`。「線上付款」按鈕只給公司的老闆（ERPNext System Manager）看。

公司資料要填：**聯絡人 Email**（收帳單與 B2C 發票）、**統編**（有填就開三聯式）、**發票地址**（有統編時綠界要求）。在營運後台公司頁下面的表單改。

營運後台最上面會寫目前接的是「綠界正式」還是「測試環境」。正式上線前請確認那一行是「綠界正式」。

## 健康度

每家公司 0–100 分，從 100 開始扣，算法在 `glue/src/health.ts`（純函式，有單元測試）。用量每天 02:00 從各家 ERPNext 收（`dropout_core.team.usage`）。

| 看什麼 | 扣分 |
| --- | --- |
| 7 天活躍人數 | 7 天沒有人用 −30；不到三成的帳號在用 −15（舊版 ERPNext 沒回 7 天數字時改看 30 天） |
| 最近有人用 | 超過 14 天 −20；超過 7 天 −10 |
| 單據量趨勢（銷貨發票） | 60 天都沒開單 −10；近 30 天不到前 30 天的一半（前 30 天至少 5 張才算）−15 |
| 續約狀態 | 只能看或暫停 −30；寬限中 −20；30 天內到期 −10；試用剩 7 天內 −10 |
| 未付帳單 | 帳單開了超過 30 天還沒付 −15（30 天內只列出來，不扣分） |
| 讀不到用量 | −10 |

最低 0 分。**未滿 50 是高風險，50–74 要注意，75 以上健康**；已解約的不算分。每一項扣分都會寫成一句話列在分數旁邊，例如「7 天只有 2／10 人在用」「帳單 45 天未付」。

營運後台的公司清單預設高風險排最前面，也可以切回依到期排序。看到高風險就先打電話或約顧問到現場，不要等到期。

算法刻意簡單，方便看得懂為什麼扣分。要改權重就改 `health.ts` 和這張表，測試在 `glue/test/billing.test.ts`。
